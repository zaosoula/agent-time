## Tracking reliability work — prepared 2026-10-20, released in beta.5

Branch `feat/tracking-reliability-roadmap` introduced per-source capture states including browsers, bounded collector restart, targeted hook repair, first-event setup feedback, privacy exclusions that discard browser samples when a site exclusion cannot be checked, timed pause, bulk daily review, manual notes, weekly review/export, an opt-in redacted JSON support bundle, verified SQLite archive import and explicit deletion, storage breakdown and WAL reclamation, background update checks, and a widget route to capture health. Its local verification passed 215 JavaScript tests, 15 locked Rust tests, and the interface build. An earlier Apple Silicon app build passed strict nested signature verification and packaged `agenttime` URL scheme inspection; it predates the 2026-10-21 storage changes. That build used local development signing and was **not notarized or published**. The signed beta.5 release above supersedes this preparation build.

On a read-only local store with 558,638 events and a 434,417,664-byte database, the new indexed startup settings query read 179 relevant records in about 1 ms; the prior startup code loaded and parsed all events. The offline compactor verified a disposable copy with 516,870 events and 413,798,400 bytes, preserving timing, other coverage, review decisions, integrity, and the static Orca host-scope notice on all nine observed days. The copy saved 20,619,264 bytes (about 4.7%) and was deleted after measurement. Full summary replay still takes about 3 seconds and is a release performance limitation. A shorter date window happened to match sampled days but was not shipped because a valid observed span may cross its boundaries. No live history retention or deletion was introduced.

The preparation checklist called for bounded daily projection, a versioned Developer ID signed and notarized candidate, real widget and timed-pause checks, clean first run, and signed OTA. For beta.5, the release owner accepted the measured full-history summary limit; the other checks are recorded above. The earlier development-signed build was never promoted.

On 2026-10-21, the branch added explicit restart-time storage replacement. A disposable snapshot of the 558,638-event store completed the prepare, verify, replace, reopen, and integrity-check path, reducing to 516,870 rows and saving 17,047,552 bytes relative to the already-vacuumed snapshot. Focused tests cover rollback to the original archive, stale-source rejection, interrupted replacement, and malformed archive rejection. The installed app's live database was unchanged. This rehearsal does not establish release-machine behavior or a supported automatic retention policy.

Status: **`0.2.0-beta.5` published on 2026-10-21** for Apple Silicon. The public site offers its signed and notarized DMG, and the HTTPS feed serves its signed in-app update. Clean first run, widget gallery rendering, and beta.4-to-beta.5 OTA were observed on the Mac mini test account; the release Mac confirmed real Claude Code and Codex hook delivery after its OTA update.

## First-run incident — 2026-10-19

Two testers reported that capture stayed in “Checking…” and the collector exited; one also reported that the window could not be moved. The app showed an update-check error. The exact public `beta.1` DMG (SHA-256 above) reproduced the collector crash on the release Mac: its Hardened Runtime signed Node sidecar terminated before loading the collector with `Failed to reserve virtual memory for CodeRange`. A local copy signed with only `com.apple.security.cs.allow-jit` started the packaged collector from an isolated home directory. The `main` window capability lacked `core:window:allow-start-dragging`, which Tauri requires for the existing drag regions. The unpromoted update endpoint returned 404; the updater accepts 204 as “no update.”

The installer selection was removed from the public landing page through the feed service on 2026-10-19. The page remained online and direct installer requests for the withdrawn version returned 404. The earlier signed/notarized status alone did not prove runtime function.
