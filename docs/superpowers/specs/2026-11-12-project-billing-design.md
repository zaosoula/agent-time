# Project billing: accepted design

User approved a project-first billing model and corrected the configuration storage: SQLite is canonical, edited through project settings. JSON is optional exchange only. Preserve all captured events, existing timing semantics and manual decisions.

A stable billable project groups repository roots/worktrees, explicit workspace IDs and reported project names; unique aliases resolve to it. Versioned effective-date policies select human-only, human/agent union (default), human + weighted agent-only, or explicitly labelled human + weighted cumulative agent time. Rates/currency are explicit; optional agent-only rate, fraction weight, minute/15minute/hour rounding by day/period, daily cap, optional recent human-message gate and none/actual/flat AI fees. Unknown amounts stay null. Parent/child usage is never summed twice.

Calculate billing on raw intervals in seconds, not already minute-credited metrics. Deduplicate across every repository within one billable project before pricing. Exclude known sleep/lock and report missing coverage. Presence gates require captured human-message evidence, never passive foreground or invented transcript data. Declared task timers do not automatically become billable time. Cross-project overlap is flagged for review rather than silently reallocated. Retain policy versions and saved report results so later edits do not rewrite exports.

MCP adds billing_projects and billing_for_project(project,fromDate,toDate,format=json|csv|markdown,detail=summary|daily,cursor?). Existing time_for_project gains compact summary and explicit unknown/ambiguous resolution. Long summary/billing ranges stream bounded daily windows, no 30-day failure, no accumulated raw history. Reports expose daily and total raw metrics, exclusions, weighted/rounded/capped units, time amount, separate AI fee, completeness and plain explanation. Exports are generated locally from saved reports, not giant MCP strings.

Implementation rulings: default rounding nearest minute per period; money stored as decimal strings with currency-aware precision; new UI edits append policy versions (same-policy mutation rejected); project mappings can be updated but existing saved reports remain immutable. Optional actual AI fees disclose missing/incomplete/unverified usage. Mixed currencies in one report are rejected. Configuration writes occur through app IPC; MCP reads and calculates only.
