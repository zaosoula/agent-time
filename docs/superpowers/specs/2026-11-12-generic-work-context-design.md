# Generic measured-work context — accepted scope

The user approved the generic adaptation of the four agent-timesheet requests, after explicitly distinguishing a customer request from implementation approval. Implement launcher context, measured-agent reads, bounded attributes and ordinary Git-worktree grouping; keep ERP identities/mappings, timesheet creation and validation in the external consumer. No ERP API, webhook or dedicated ERP database columns.

Preserve native event/session/child identities and existing timing, grouping and minute-credit calculations. Business identity is `agentIdentity`, profile is `agentProfile`, and native `agentId` retains its existing child/session meaning. A native `agent_type`/`data.childType` is a profile, not an inferred unique business identity. Queries use explicit `agentIdentityId` and `agentProfile` filters; filtered human time is not claimed by an agent.

Launcher opt-in: read `AGENT_TIME_AGENT_ID` and `AGENT_TIME_ATTR_*` only, never unrelated environment values. Store identity/attributes in hook data; preserve other normalized hook fields. Attribute suffixes become lowercase keys, e.g. KANZEN_PROJECT_ID → kanzen_project_id. Metadata limits: 16 keys, 64 characters/key, 128 characters/value, 1024 UTF-8 bytes total; keys `[a-z][a-z0-9_.-]*`, case normalized, prototype-sensitive keys/control characters/case collisions rejected. Empty values explicitly remove inherited keys when applying declaration overrides. Invalid launcher metadata is omitted with a fixed non-sensitive warning; telemetry timing still records. Shared report cap 4096 UTF-8 bytes, used by both validator and pending-spool reader.

MCP `set_work_context` and `start_task` accept the same generic attributes. Launcher baseline → latest preceding session declaration → explicit task overrides. Task metadata is frozen at start and remains retry-safe. An empty attributes object adds no overrides; empty-string values clear inherited keys. Native session keys remain unchanged. Expose bounded context slices/contributors with source evidence and provenance when metadata changes; never put one arbitrary attributes map on a segment containing concurrent agents, or re-round split metadata slices as new measured blocks. Default unfiltered totals stay identical.

Bound retained metadata per summary window; intern repeated metadata maps rather than retaining a process-global unbounded pool. Update standalone copied hook runtime dependencies and tests, not only the app package.

Ordinary linked Git worktrees resolve to their principal checkout from git-common-dir metadata, with a bounded cache and filesystem-first resolution; bounded fixed-argument Git fallback may handle nonstandard layouts. Keep Orca behavior and normal non-worktree/subproject paths. Preserve raw cwd and persist optional canonical projectPath so new observations remain attributable after a worktree is deleted. Resolve filesystem state only for a compatible local host. Missing/deleted historical evidence remains unknown rather than guessed. Browser helpers remain pure and prefer propagated projectPath.

Release only after focused/full tests, independent review, packaged hook/MCP/IPC checks, signing/notarization and public-byte verification. Existing billing rules/reports remain intact.
